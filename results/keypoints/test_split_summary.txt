Limitations, stated with the results rather than discovered afterwards:
  1. The test images are contrast-equalised and the evaluation clips are not.
     Roboflow applied adaptive equalisation to every image in this dataset, so a
     clips-versus-test comparison confounds genuine domain gap (different
     broadcasts, different courts) with a preprocessing mismatch. K4 predicts
     degradation without separating the two, and this script cannot separate them
     either. Ablation A2 is the measurement that addresses it.
  2. Ground truth here is Roboflow's annotation, not this project's. Its quality
     is unknown and unaudited, unlike the possession and keypoint-audit ground
     truth. A large measured direct error could be model error or annotation
     error, and this measurement cannot distinguish them.
  3. Reprojection is measured only on images already carrying at least five
     confident keypoints, so the images where localisation error is most
     suspected are precisely the ones excluded — the same coverage limitation the
     clip measurement carries, and the reason the two are comparable.
  4. COMPARE THE TEST SPLIT AND THE CLIPS ON METRES, NOT PIXELS. The split spans
     six resolutions — 1280x720 (92 images), 2336x1752 (49), 1624x1234 (32),
     640x360 (19), 1920x1080 (16), 2456x2054 (12) — whose diagonals differ by
     roughly 6.8x, and the most common is only 42% of the split. A pooled median
     of raw pixel residuals is therefore dominated by which resolutions happen to
     be present rather than by localisation quality. The pixel column is retained
     because the clip table reports raw pixels and normalising here would break
     the comparability this script exists to provide, but it is indicative only.
     Metres are resolution-independent, being measured on the court plane, and are
     the column the clips-versus-test comparison must be made on. Direct error
     carries a normalised column instead precisely because it has no clip-side
     counterpart to stay comparable with.
  5. THE TWO MEASUREMENTS USE DIFFERENT INFERENCE PATHS, UNVERIFIED. The clip
     script infers in batches of 20 through CourtKeypoints.run_detection(), while
     this script calls detect_keypoints() on one image at a time. Ultralytics
     letterboxes a batch to a common input shape, so a batched prediction and a
     single-image prediction are not guaranteed numerically identical — and this
     script exists to produce a residual comparable with the clip table. Whether
     the two paths agree HAS NOT BEEN CHECKED; it needs the checkpoint and the
     dataset, so it is a JupyterHub task. Treat any small clips-versus-test
     difference as potentially an artefact of this until it is verified.
  6. No keypoint cache is written or fingerprint-validated by this script. Per-
     image inference has no cache_path, unlike run_detection(), so every re-run
     re-infers all 220 images and no stale-cache check protects these numbers the
     way it protects the clip measurement.
